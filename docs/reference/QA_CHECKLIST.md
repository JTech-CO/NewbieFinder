# QA 체크리스트

- 대상 제품: NewbieFinder v1.0.0
- 최종 갱신일: 2026-08-11
- 근거: 백서 20장(디자인 QA), 9.3(E2E), 9.4(UI·접근성), 9.5(비기능), 9.7(출시 승인 기준)

출시 전에 이 문서를 위에서 아래로 한 번 통과시켜 주세요. 자동화된 테스트(`npm run test`, `npm run test:e2e`)로 덮이는 항목이라도, 실제 브라우저에 로드한 상태에서 최소 1회 수동 확인합니다.

**검증 환경**

- 빌드: `npm run build` 로 만든 `dist/` 를 `chrome://extensions` 개발자 모드에서 Unpacked 로드
- 브라우저: Chrome 120 이상, 테스트 전용 프로필
- 해상도: 1280×720 / 1440×900 / 1920×1080

---

## 1. 레이아웃 (백서 20.1)

- [ ] 1280px 폭에서 사이드바와 결과 그리드가 겹치지 않습니다.
- [ ] 600px 미만에서 단일 열로 전환됩니다.
- [ ] 긴 방송 제목이 카드 높이를 무너뜨리지 않습니다. (제목 최대 2줄, 채널명 1줄 말줄임)
- [ ] 필터 입력값이 3자리(예: `100`)에서도 잘리지 않습니다.
- [ ] Sticky 헤더가 포커스 대상과 겹치지 않습니다.
- [ ] 카드 최소 폭 280px 기준으로 열 수가 자동 결정됩니다.
- [ ] 썸네일이 없어도 카드의 정보 구조가 유지됩니다.
- [ ] 결과가 추가될 때 기존 스크롤 위치가 유지됩니다.

## 2. 화면 상태 (백서 20.2 / 21.3)

- [ ] Loading, Ready, Partial, Stale, Error 상태가 시각적으로 구분됩니다.
- [ ] 두 기본 필터를 모두 끄면 최근 시작 순이 즉시 비활성화됩니다.
- [ ] 팔로워 미확인 상태를 `0명` 으로 표시하지 않습니다.
- [ ] 이전 캐시를 실시간 데이터처럼 표시하지 않습니다. (`이전 데이터 · N분 전 갱신` 배지 노출)
- [ ] 계약 오류 상태에서 잘못된 카드를 만들지 않습니다.
- [ ] 완전 탐색과 부분 탐색의 문구가 서로 다릅니다.
- [ ] 캐시 갱신 시각이 화면에 명확히 표시됩니다.
- [ ] 팔로워 판정 중인 후보 수가 표시됩니다.
- [ ] 모든 오류 상태에 재시도 버튼 또는 설명이 있습니다.
- [ ] 조건을 하나도 켜지 않은 상태에서 조건 선택 안내가 표시됩니다.

## 3. 브랜드 (백서 20.4 / 11.4)

- [ ] CHZZK 공식 로고를 사용하지 않습니다.
- [ ] 비제휴 고지가 Footer에 상시 보입니다.
- [ ] "뉴비" 정의 고지가 Footer에 상시 보입니다.
- [ ] NewbieFinder 강조색이 공식 인증 표시처럼 사용되지 않습니다.
- [ ] 과도한 네온·사이버펑크 효과를 사용하지 않습니다.
- [ ] "공식", "파트너", "인증" 으로 오인시키는 문구가 없습니다.
- [ ] "무조건", "완벽", "모든 방송" 같은 과장 표현이 없습니다.
- [ ] 모든 사용자 노출 문자열이 존댓말입니다.
- [ ] 금지 용어를 쓰지 않습니다. (동접자 / 구독자 수 / 신생 방송 순 / 크롤링 중 / 대략적인 전체 결과)

## 4. 성능: 화면 (백서 20.5)

- [ ] 카드 이미지가 Lazy Load 됩니다. (`loading="lazy"`, `decoding="async"`)
- [ ] 기존 결과가 갱신될 때 레이아웃 이동이 적습니다.
- [ ] 300개 카드에서도 스크롤이 눈에 띄게 끊기지 않습니다.
- [ ] 각 카드가 독립 타이머를 만들지 않습니다. (공유 클럭 1분 주기)

## 5. E2E 시나리오 (백서 9.3)

테스트 전용 프로필에 확장을 로드한 상태에서 순서대로 진행합니다.

- [ ] 확장을 테스트 프로필에 Unpacked로 로드했습니다.
- [ ] 일반 사이트(예: `https://example.com`)에서 툴바 아이콘이 비활성입니다.
- [ ] `https://chzzk.naver.com/` 에서 툴바 아이콘이 활성입니다.
- [ ] 아이콘을 클릭하면 Finder 페이지가 **새 탭**으로 열립니다.
- [ ] 팝업이 열리지 않습니다.
- [ ] 원래 치지직 탭이 변경되지 않은 채 남아 있습니다.
- [ ] 최초 실행 시 기본 조건(시청자 10명 이하)이 표시됩니다.
- [ ] 두 기본 필터를 모두 끄면 최근 시작 순 컨트롤이 비활성화됩니다.
- [ ] 팔로워 조건을 켜면 진행 상태(판정 중 카운트)가 표시됩니다.
- [ ] 결과 카드 링크가 `https://chzzk.naver.com/{channelId}` 형태의 올바른 HTTPS 주소입니다.
- [ ] 카드 링크에 `noopener`, `noreferrer` 가 적용되어 있습니다.
- [ ] 새로고침 버튼이 동작하고 20초 쿨다운이 적용됩니다.
- [ ] 브라우저를 재시작해도 마지막 설정이 복원됩니다.
- [ ] 확장을 제거하면 저장된 로컬 데이터가 함께 제거됩니다.

### 5.1. 데이터 상태 시나리오 (백서 9.2 연계)

- [ ] 라이브 2페이지 중 2페이지가 실패하면 1페이지 결과를 부분 결과로 표시합니다.
- [ ] 채널 20건 중 3건 실패 시 17건 판정 / 3건 미확인으로 나뉘어 표시됩니다.
- [ ] `429` 발생 시 큐가 중단되고 부분 결과로 표시됩니다. 추가 요청이 나가지 않습니다.
- [ ] 신선 캐시가 있으면 네트워크 응답 전에 즉시 결과가 표시됩니다.
- [ ] 오래된 캐시 + 네트워크 실패 조합에서 이전 데이터 배지와 함께 표시됩니다.
- [ ] 스키마가 바뀐 응답을 주면 카드 렌더링이 중단되고 계약 오류가 표시됩니다.
- [ ] 요청 진행 중 필터를 바꿔도 상태가 꼬이지 않습니다.
- [ ] 새로고침을 연타해도 쿨다운 동안 추가 요청이 발생하지 않습니다.
- [ ] 오프라인 상태에서 진입 시 안내와 함께 이전 결과(있는 경우)가 표시됩니다.

## 6. 접근성 (백서 20.3 / 9.4)

### 6.1. 키보드

- [ ] 모든 필터 조작을 키보드만으로 할 수 있습니다.
- [ ] Tab 순서가 시각적 순서와 일치합니다.
- [ ] Space 또는 Enter로 토글 스위치를 조작할 수 있습니다.
- [ ] 방향키로 Range 슬라이더를 조작할 수 있습니다.
- [ ] 모든 상호작용 요소에 포커스 링이 보입니다.
- [ ] 포커스가 화면 밖 요소로 이동하지 않습니다.

### 6.2. 스크린 리더

- [ ] 모든 입력에 연결된 레이블이 있습니다.
- [ ] 스위치의 켜짐/꺼짐 상태가 스크린 리더에 전달됩니다.
- [ ] 결과 개수 갱신이 Live Region으로 안내됩니다.
- [ ] 상태 배너(부분 결과, 이전 데이터, 오류)가 스크린 리더에 전달됩니다.
- [ ] 카드 이미지의 `alt` 가 적절합니다. (중복 텍스트가 과하면 빈 `alt` 로 장식 처리)

### 6.3. 시각

- [ ] 주요 텍스트와 컨트롤의 대비가 WCAG 2.2 AA 이상입니다.
- [ ] 색각 이상 시뮬레이션에서 상태 구분이 색에만 의존하지 않습니다.
- [ ] 200% 확대에서 가로 스크롤 없이 핵심 기능을 사용할 수 있습니다.
- [ ] 320%, 400% 확대에서도 핵심 컨트롤을 사용할 수 있습니다.
- [ ] `prefers-reduced-motion` 에서 불필요한 움직임이 사라집니다.

### 6.4. 콘텐츠 내성

- [ ] 긴 한글 제목이 레이아웃을 깨뜨리지 않습니다.
- [ ] 이모지가 포함된 제목이 정상 표시됩니다.
- [ ] 영문·숫자·한글이 섞인 제목이 정상 표시됩니다.
- [ ] 이미지가 없거나 로드가 느린 경우 대체 이미지가 표시됩니다.
- [ ] 허용 목록 밖 호스트의 썸네일 URL이 대체 이미지로 처리됩니다.

## 7. 비기능 (백서 9.5)

### 7.1. 권한·보안

- [ ] manifest의 권한이 `declarativeContent`, `storage` 두 가지뿐입니다.
- [ ] 호스트 권한이 `https://api.chzzk.naver.com/*` 하나뿐입니다.
- [ ] 네트워크 탭에서 API 호스트 외 다른 호스트로 요청이 나가지 않습니다. (이미지 CDN 제외)
- [ ] 패키지 안에 원격 코드, `eval`, 인라인 스크립트가 없습니다.
- [ ] 콘솔에 CSP 위반 경고가 없습니다.
- [ ] 로그인 쿠키를 읽는 코드가 0건입니다.
- [ ] 모든 API 요청에 `credentials: "omit"` 이 적용되어 있습니다.
- [ ] `innerHTML`, `dangerouslySetInnerHTML` 사용이 0건입니다.
- [ ] 원격 폰트나 CDN 스타일시트를 로드하지 않습니다.
- [ ] 프로덕션 빌드에 디버그 로그가 남지 않습니다.
- [ ] `npm run validate:manifest` 가 통과합니다.

### 7.2. 요청 제어

- [ ] 채널 조회 큐의 동시성이 4를 넘지 않습니다. (300개 조회 시 확인)
- [ ] 동일 `channelId` 요청이 In-flight 중복 제거로 합쳐집니다.
- [ ] `429` 응답에서 요청이 폭주하지 않고 즉시 중단됩니다.
- [ ] 라이브 목록 요청이 순차(동시 1)로 진행됩니다.
- [ ] 탭을 닫거나 새로고침하면 진행 중 요청이 `AbortController` 로 중단됩니다.
- [ ] 화면을 닫은 뒤 장기 Polling이나 타이머가 남지 않습니다.
- [ ] 유휴 상태에서 네트워크 요청이 발생하지 않습니다.

### 7.3. 자원

- [ ] 메모리 스냅샷 비교에서 반복 새로고침 후 누수가 관찰되지 않습니다.
- [ ] 300개 카드 렌더링 시 스크롤 성능이 유지됩니다.
- [ ] `chrome.storage` 사용량이 목표치(5MB) 이하입니다.
- [ ] TTL이 지난 캐시가 정리됩니다.
- [ ] 캐시 항목 상한(채널 2,000 / 라이브 후보 1,500)이 지켜집니다.
- [ ] 초기 JS 번들이 gzip 기준 250KB 이하입니다.

### 7.4. 성능 목표 (백서 2.8.2)

- [ ] Finder UI 셸이 500ms 이내에 표시됩니다.
- [ ] 유효 캐시 결과가 300ms 이내에 표시됩니다.
- [ ] 정상 네트워크에서 첫 후보가 2.5초 이내에 표시됩니다.
- [ ] 필터 재계산이 후보 10,000개 기준 50ms 이내입니다.

## 9. 회귀 확인 메모

계약 검증(`npm run contract:live`)은 **수동 실행 전용**입니다. 릴리스 직전 1회만 실행하고, 실패가 접근 제한을 의미하는 경우 우회하지 않고 출시를 보류합니다. 자세한 판단 기준은 [`CONTRACT_RISK.md`](./CONTRACT_RISK.md)에 있습니다.
